The system relies on Streamer.bot (C# inline methods), a shared local SQLite database (optimized for concurrent reads by an offline Minecraft server plugin), and a Vanilla JavaScript/HTML/CSS OBS Browser Source overlay.

# 1. Tech Stack & Architecture Requirements
*   **Backend / Bot:** Streamer.bot using C# inline methods. Must be lightweight and minimize unnecessary Twitch API calls.
*   **Database:** SQLite. **Crucial:** Must be configured with `PRAGMA journal_mode=WAL;` to handle concurrency, allowing Streamer.bot to write while the local Minecraft server plugin reads simultaneously without database locking or corruption.
*   **Frontend / Overlay:** Pure Vanilla HTML/JS/CSS (Strictly NO frameworks like React, Vue, or jQuery).

# 3. Core Features & Logic

### A. Points & Sinks
*   **Accumulation:** Users earn 1 point per 1 minute of watch time (Loyalty system).
*   **Point Sink:** `!annuncio [message]` command. Deducts 150 points from the user and triggers a WebSocket event to display the message as an on-screen overlay.

### B. Betting System & Rank Workflow (Strict Execution)
*   Bet commands for two outcomes (e.g., Win/Loss).
*   Manual resolution via broadcaster commands (2.0x payout or total loss).
*   **Rank Recalculation Workflow:** Rank recalculation MUST be triggered exclusively during the payout phase to ensure data integrity:
    1. Perform a 'pre-payout' rank snapshot immediately before points are distributed.
    2. Distribute/deduct points.
    3. Calculate new ranks.
    4. Store the difference (delta) in a `rank_change` column in the SQLite DB (applies to both Lifetime and Seasonal tables).

### C. Database Storage & Leaderboards
The SQLite database must store: User Rankings (Rank ID/Name), Global Lifetime Points, Current Season Points, Win Rate stats, Total points wagered, and Last bet timestamp.
*   **Win Rate Leaderboard Logic:** Formula is `(Wins / Total Bets) * 100`.
    *   *Minimum Qualifiers:* At least 10 total bets AND 400 total points wagered.
    *   *Activity Filter:* Only users who have placed at least one bet in the last 5 days are pulled for this leaderboard.
*   **Seasonal Resets:** A C# script/method to perform a monthly points reset. **Crucial:** It sets the *Current Season Points* back to zero for everyone, but must NOT delete historical rank, lifetime points, or lifetime stats.

# 4. Visual Integration & Chat Overlay

### WebSocket Payload
For every chat message received, Streamer.bot must push a JSON payload containing:
*   Message text
*   Username
*   Rank ID & Rank Icon path (Seasonal)
*   Current Point Balance
*   `lifetimePeakRankColor` (Hex code or CSS class string representing the user's highest lifetime rank).

### UI/UX Rules (The "Legacy Aura")
*   **Current Season Icon:** The icon displayed next to the name reflects the Current Season Rank (resets monthly). Assume icons are provided locally (e.g., `/icons/wood.png`).
*   **Legacy Text Shadow:** The username must have a CSS `text-shadow` (glow effect) colored based on the `lifetimePeakRankColor`. Example: A user who once reached Master will always have a purple glow, even if their current season icon is Wood. 
*   **Format:** `[RankIcon] Username (Points): Message`.
